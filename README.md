# Beauty Crib

A complete front-end prototype for Beauty Crib, an online beauty and cosmetics shop serving Uganda.
Premium editorial design, strictly black and white, built so it can be rebuilt in
WordPress + Elementor + WooCommerce without redesigning anything.

**68 pages**, 17 products, 6 journal articles, a working bag, wishlist, filtering, search and checkout.

---

## Run it

```bash
node tools/serve.js
```

Then open <http://localhost:4173>. The server treats `website/` as the site root, so every
absolute path behaves exactly as it will on the live domain.

## Rebuild after editing

```bash
node src/build.js      # regenerate all 68 HTML pages from src/
node tools/audit.js    # SEO, links, alt text, image size and heading checks
node tools/images.js   # re-run the image pipeline (only needed for new photography)
node tools/logo.js     # re-trace the logo files (rarely needed)
```

## Where things live

```
Products/                 Original photography, untouched
*.jpg, *.png              Original brand and lifestyle assets, untouched

src/                      Everything that is authored
  data/
    products.json         The 17 products: copy, prices, skin types, benefits, how to use
    categories.json       Category tree, intros and SEO text
    articles.json         The 6 Journal articles
    site.json             Contact details, delivery methods, payment methods  <-- edit this first
    images.json           Generated by tools/images.js. Do not edit.
  pages/                  One file per unique page, containing only its sections
  templates/              Product, category and article templates
  partials/               Header, footer, cart drawer, search overlay, filters
  layout.html             The page shell
  build.js                Renders everything into website/

website/                  The built site. HTML here is generated; assets are authored.
  assets/css/             tokens, base, components, pages
  assets/js/              store, ui, and one small file per page type
  assets/img/             Optimised responsive images (WebP + JPEG, max 1500px)
  assets/fonts/           Instrument Serif and Instrument Sans, self-hosted

tools/                    images.js, logo.js, serve.js, audit.js
ELEMENTOR-MAP.md          Every section mapped to its Elementor widget
WOOCOMMERCE-SETUP.md      How to rebuild this as a working WooCommerce store
```

**Rule of thumb:** edit `src/`, never `website/*.html`. Those files are overwritten on every build.

## Editing content

| To change | Edit | Then |
|---|---|---|
| Phone, WhatsApp, email, address, social links | `src/data/site.json` | `node src/build.js` |
| Delivery rates and timings | `src/data/site.json` → `delivery.methods` | `node src/build.js` |
| Payment methods shown at checkout | `src/data/site.json` → `payments` | `node src/build.js` |
| A product's price, copy, skin type | `src/data/products.json` | `node src/build.js` |
| Category intros and SEO text | `src/data/categories.json` | `node src/build.js` |
| A journal article | `src/data/articles.json` | `node src/build.js` |
| A page's sections | `src/pages/<page>.html` | `node src/build.js` |
| Colours, type scale, spacing, motion | `website/assets/css/tokens.css` | nothing, it is live CSS |

### Delivery pricing

Rates were not supplied, so every delivery method has `"cost": null`, which the site shows as
"Confirmed on order" and excludes from the total. Put a number in and the prototype prices and
totals it automatically:

```json
{ "id": "kampala", "label": "Kampala delivery", "eta": "Same or next day", "cost": 10000 }
```

## Placeholders waiting on the business

These were left as clearly marked placeholders rather than invented. All live in `src/data/site.json`.

1. **Phone and WhatsApp** — currently `+256 7XX XXX XXX`
2. **Email** — currently `hello@beautycrib.ug`
3. **Physical address and collection point** — currently "Kampala, Uganda"
4. **Opening hours** — a sensible default is in place
5. **Social handles** — links point at the platforms, not at your accounts
6. **Delivery rates and free-delivery threshold** — see above
7. **Payment provider** — the checkout shows MTN MoMo, Airtel Money, card, bank transfer and cash on
   delivery without naming a provider. Pick one in `WOOCOMMERCE-SETUP.md`.
8. **Returns window** — set to 7 days
9. **Registered company name** for the legal pages
10. **Product sizes in ml or g** — not printed anywhere in the supplied photography
11. **Full ingredient lists** — product pages list key ingredients and tell customers the full list is
    on the carton, rather than publishing an unverified INCI list

The Privacy Policy and Terms are working drafts written for Ugandan online retail and should be
reviewed by a qualified adviser before launch.

## Design system in one paragraph

Black `#000` and white `#fff`, with Soft Black `#111` for inverted chapters, Off White `#F7F7F5`
behind product photography, Light Gray `#E8E8E5` for hairlines and `#666` for small secondary text
(`#777` fails AA at body sizes, so it is reserved for large text). Display type is Instrument Serif,
interface type is Instrument Sans, both self-hosted under the SIL Open Font License as stand-ins for
PP Editorial New and PP Mori. Layout is Flexbox only, no CSS Grid, so every row maps to an Elementor
container. Motion is CSS transitions driven by a small observer: fade-up reveals, a clip-path image
reveal, gentle parallax on two images, and drawer transitions. All of it respects
`prefers-reduced-motion`, and nothing is hidden when JavaScript is unavailable.

## What was verified

- Every page at 1440, 1024, 768 and 390 px with no horizontal overflow
- Add to bag, quantity, remove, bag drawer, wishlist, filters, sort, load more, search, journal
  filtering, gallery lightbox, accordions and tabs
- A full checkout: validation, Uganda phone format, order placement, confirmation page, account order
  history
- `node tools/audit.js`: 68 pages, 5,742 internal links, 680 images, no dead links, no missing
  images, every image has alt text and dimensions, one `h1` per page, titles within 62 characters,
  meta descriptions within 165
- **axe-core 4.10 accessibility scan: zero violations** across home, shop, category, product, cart,
  checkout, order confirmation, journal, article, gallery, contact, FAQ, login, register, account,
  search and the policy pages
- Largest image 140 KB, nothing wider than 1500 px, 73 KB CSS and roughly 30 KB of JavaScript per page
  before compression
